# 延迟与过载验证

[English](PERFORMANCE.md) · [系统架构](../ARCHITECTURE.zh-CN.md) · [资源配置](CONFIGURATION.zh-CN.md)

## 范围与方法

资源探针启动隔离的 Service/Web，生成有权限的本地模型来源，测量 HTTP 延迟并注入过载/故障，不连接真实模型。临时库、密钥和日志全部位于项目 tmp。

```sh
cargo build --locked -p boost-service -p boost-web -p boost-start
node scripts/probe-resource-limits.mjs
```

使用 `--output=<路径>` 保存 JSON，只有明确调试时使用 `--keep`。默认关闭探针创建的进程并清理专属目录，不终止用户实例。

## 环境与数据

Windows x64、AMD Ryzen 7 8745H、16 逻辑处理器、约 23.3 GiB 内存、Node 24.12.0、Rust debug 程序。基线 mock 模型延迟 25ms，另有慢请求、503 注入和健康来源切换。下表为一次本机观测，不是供应商 SLA 或跨硬件容量承诺。

| 直连管理并发 | 请求数 | P50 ms | P95 ms | P99 ms | 请求/秒 |
| --- | --- | --- | --- | --- | --- |
| 1 | 256 | 0.72 | 1.54 | 2.00 | 1173.7 |
| 6 | 256 | 2.94 | 6.55 | 9.58 | 1810.2 |
| 16 | 256 | 5.45 | 13.50 | 14.41 | 2412.4 |
| 32 | 256 | 9.56 | 15.02 | 16.32 | 3220.5 |
| 64 | 256 | 17.55 | 31.58 | 32.24 | 3331.8 |

该阶段 1,280 个管理请求全部成功；方法读取监听配置，是轻量管理链路测量，不是批量导入或数据库写吞吐。

## 隔离与过载

| 场景 | 观测 |
| --- | --- |
| Web RPC，6 客户端/60 请求 | P50 2.72ms、P95 5.73ms、P99 5.76ms |
| 8 个慢模型请求期间的管理调用 | 60/60 成功，P99 12.02ms |
| 32 客户端突发/128 推理请求 | 13 成功、115 明确 429；全部响应 P99 79.74ms |
| 8 秒持续饱和，32 客户端，默认 20 QPS | 22,640 次：179 成功、22,461 明确 429；全部响应 P99 24.45ms |
| 饱和期间服务 RSS | 观测峰值 74,862,592 字节，约 71.4 MiB |
| 结束后队列 | 无等待写、无活跃写；遥测查询自身占一个读许可 |

突发和饱和分位数包含拒绝请求，不能当作成功模型完成延迟。默认突发桶允许启动阶段超过稳态 QPS。

Web 修正移除了鉴权热路径反复打开连接和初始化 schema；同一 fixture 的早期对照 P50 约 51ms，改为专用设置连接后约 2ms。设置读取独立于推理池，避免嵌套获取导致耗尽。

## 故障与正确性

- Responses/Chat Completions 的 JSON/SSE 和工具定义传递。
- 缺少平台 key 拒绝。
- 熔断打开后不再向故障来源发送请求。
- 独立健康来源可承接切换。
- HTTP 流取消后在后端清理结束时释放容量。
- 完整主库用私有密钥文件转换并重新打开。
- Bot 转换验证 schema、中文、BLOB、64 位整数、rowid、自增序号、触发器和版本。
- 存储内联回归在长读快照存在时完成 8 写线程、800 次立即事务。
- 并发重复钱包结算只扣一次，用量失败回滚结算身份。

## 适用边界

准入按进程计算。多服务进程、大输出、上游隐藏上下文、媒体 Token、文件系统错误和真实上游延迟需要目标部署测试。8 秒负载不是长期无泄漏证明；输入缓冲预算不包含所有适配副本、分配器和输出。

保持活跃/等待有界，观察拒绝率，每次调整一个资源边界。Nginx keepalive 和 worker 不会增加上游配额。部署容量应使用生产构建及代表性输入测量。
