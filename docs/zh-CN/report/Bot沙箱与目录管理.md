# Bot 沙箱与目录管理

在 Bot「设置 → 数据与智能体 → 存储」中填写**运行 Boost 的电脑上的绝对文件夹路径**，然后保存。网页版填写的是服务器路径。留空保留当前目录。

选择 `D:\AI` 后，工作文件按以下结构整理；选择的文件夹已经叫 Boost 时不会再嵌套一层 Boost：

```text
D:\AI\Boost\bots\<工作台标识>\workspaces\<智能体标识>\
  app\        # 已安装智能体的应用与状态
  tasks\      # 后台任务（按实际任务创建）
  rules\      # 自动规则（按实际规则创建）
  handoffs\   # 群协作交付文件（按实际交付创建）
```

工作台标识由原数据目录生成，不包含账号或凭据。同一个父目录中的不同工作台使用独立目录。数据库、模型密钥、渠道凭据、代理运行时和授权资料保留在原内部数据目录。

**保存后重启 Boost 生效。**运行中的任务继续使用当前目录；下次启动在取得数据目录锁、启动渠道与任务调度之前迁移文件。界面分别显示当前目录与待迁移目录。执行、已安装应用、生成文件、渠道推送和多 Bot 文件交付使用同一个路径解析器。

迁移不会合并或覆盖已存在的目标目录。同盘使用目录移动；跨盘先复制完整内容，再切换路径。旧位置保留目录兼容链接，使历史文件和已保存的任务路径继续可用；它不是第二份文件副本，请保留该链接。跨盘复制遇到符号链接、硬链接或特殊文件会停止，避免扩大文件访问范围。迁移失败时显示原因并继续使用原目录；原子移动中断后可以依据迁移记录恢复。

路径变更不改变执行权限：只读、工作区可写和完全权限仍是每个 Bot 的独立设置。工作区读取与交付按真实路径校验，不能通过旧路径、目录链接或大小写变化访问其他 Bot 的私有工作文件和内部凭据。跨盘迁移功能已验证 EXDEV 分支，实际跨盘速度取决于文件量和磁盘性能。

## 对话中的上下文进度

模型菜单默认折叠上下文详情。已测输入与输出用量组成最近一次请求的占用值，不累加历史请求冒充当前上下文。

占用条按消息、系统工具、系统提示词、技能、项目上下文分色，条形和分类列表共用数值。未独立计量的分类显示横线；实测总量与已识别分类的差额独立以灰色「未分类用量」显示，不冒充工具或技能用量。分类估算大于实测时采用带「≈」的分类总量，避免强行缩放分类数值。超过容量时轨道封顶，分类比例仍保留。

容量优先使用模型目录提供的数据。没有目录容量时，已启动的代理提供当前实际配置的执行窗口，并标注「按当前执行窗口计算」；这个执行预算不代表模型厂商公布的最大容量。两者均未提供时按用户指定的 **128,000 Token（128K）** 默认窗口展示占比，并标明默认值。没有真实用量时使用消息与系统提示词的文本估算，数值前显示「≈」，说明不包含未计量的工具、技能等上下文，避免把估算冒充真实采样。

## Bot 数据位置

Bot「设置 → 数据与智能体 → 数据位置」支持独立迁移当前工作台的会话数据库、Bot配置、渠道凭据、记忆及运行资料。默认不更改原目录；填入运行Boost的电脑上的绝对父文件夹，保存后退出并重新启动Boost。数据按 `Boost/bots/<工作台标识>/data` 整理；留空保留当前实际位置。网页填写的是服务所在电脑的路径。

迁移在数据库、渠道、智能体启动前进行。新目录不能与原目录或现有独立沙箱互相包含，已有目标不覆盖；相同磁盘优先原子移动，跨盘使用受保护的新目录、逐文件复制及SHA-256复核。Windows为目标目录设置当前用户、SYSTEM及管理员的访问权限；其他系统使用私有目录权限。复制不跟随目录链接到其他工作台，保留链接本身；数据库、中文、换行和现有文件内容随数据保留。

旧数据路径保留为兼容链接，历史文件地址继续可用。迁移过程使用内部记录处理中断；失败保留可用的原目录并在设置中显示错误，目标冲突不删除用户文件。正在使用该数据目录的其他宿主会阻止迁移。普通启动仍使用原等待时间，确认正在迁移数据时给出最长十分钟启动窗口，避免原45秒超时中断较大目录。

已经独立放置的沙箱（例如 `E:\Boost\bots\<工作台标识>\workspaces`）保持原位置，稳定工作台标识不会因数据搬迁重新生成。未独立配置的默认沙箱是数据目录中的子目录，会随其一起移动。Boost账号池、聚合API密钥、请求日志和计费数据库不包含在此次Bot工作台数据迁移中。

路径在页面中完整换行显示；桌面版可点击“显示目录”调用系统文件管理器。网页版无法在浏览器中直接打开服务器文件夹，因此该按钮禁用并说明原因。迁移目标尚未应用时，“显示目录”定位当前实际数据目录。

内部设置：`config.json` 中的 `dataParent` 默认空字符串，保存期望父目录；`workspaceIdentity` 是迁移时写入的内部稳定标识。旧数据锚点、迁移记录和锁用于恢复与兼容，不是数据备份。
