# Bot 沙箱与目录管理

在 Bot「设置 → 数据与智能体 → 存储」中填写**运行 Boost 的电脑上的绝对文件夹路径**，然后保存。网页版填写的是服务器路径。留空保留当前目录。

选择 `D:\AI` 后，工作文件按以下结构整理；选择的文件夹已经叫 Boost 时不会再嵌套一层 Boost：

```text
D:\AI\Boost\bots\<工作台标识>\workspaces\<智能体标识>\
  app\        # 已安装智能体的应用与状态
  tasks\      # 后台任务（按实际任务创建）
  rules\      # 自动规则（按实际规则创建）
  handoffs\   # 群协作交付文件（按实际交付创建）
```

工作台标识由原数据目录生成，不包含账号或凭据。同一个父目录中的不同工作台使用独立目录。数据库、模型密钥、渠道凭据、代理运行时和授权资料保留在原内部数据目录。

**保存后重启 Boost 生效。**运行中的任务继续使用当前目录；下次启动在取得数据目录锁、启动渠道与任务调度之前迁移文件。界面分别显示当前目录与待迁移目录。执行、已安装应用、生成文件、渠道推送和多 Bot 文件交付使用同一个路径解析器。

迁移不会合并或覆盖已存在的目标目录。同盘使用目录移动；跨盘先复制完整内容，再切换路径。旧位置保留目录兼容链接，使历史文件和已保存的任务路径继续可用；它不是第二份文件副本，请保留该链接。跨盘复制遇到符号链接、硬链接或特殊文件会停止，避免扩大文件访问范围。迁移失败时显示原因并继续使用原目录；原子移动中断后可以依据迁移记录恢复。

路径变更不改变执行权限：只读、工作区可写和完全权限仍是每个 Bot 的独立设置。工作区读取与交付按真实路径校验，不能通过旧路径、目录链接或大小写变化访问其他 Bot 的私有工作文件和内部凭据。跨盘迁移功能已验证 EXDEV 分支，实际跨盘速度取决于文件量和磁盘性能。

## 对话中的上下文进度

模型菜单默认折叠上下文详情。已测输入与输出用量组成最近一次请求的占用值，不累加历史请求冒充当前上下文。

容量优先使用模型目录提供的数据。没有目录容量时，已启动的代理提供当前实际配置的执行窗口，并标注「按当前执行窗口计算」；这个执行预算不代表模型厂商公布的最大容量。两者均未提供时按用户指定的 **128,000 Token（128K）** 默认窗口展示占比，并标明默认值。没有真实用量时使用消息与系统提示词的文本估算，数值前显示「≈」，说明不包含未计量的工具、技能等上下文，避免把估算冒充真实采样。
