# 悬浮窗与本机任务监测

悬浮窗拖动后吸附显示器工作区顶部或左右边缘。顶部使用横向条，侧边使用竖向条，双击返回主窗口。点击和悬停不会展开详情。悬浮窗连接已有服务，不启动第二份服务。

在“设置 → 悬浮窗 → 显示内容”中可分别选择余量环、任务进度环、TPS 环、上传速度、下载速度和内存占用，也可隐藏环内数值。至少保留一个项目。选择保存在本机 `boost.tray.v1`，主窗口与已打开的悬浮窗即时同步，重启后保留。窗口按显示项目缩小。

## 数据来源

- 余量：已连接服务返回的当前账号 5 小时剩余额度。
- 任务：内置 Bot 状态，以及本机 Codex、Claude Code、DeepSeek Harness 的会话日志。
- TPS：Codex 输出 token 计数的增量除以实际采样时间；Claude/DeepSeek 与内置 Bot 使用日志报告的模型输出 token 数除以响应时间。采样反映最近的观测速率，包含采样区间或响应的等待时间，不等于模型供应商的纯解码速度。请求结束才报告用量的上游只能提供请求均速，不能提供逐 Token 的瞬时速率。近期有效值最多保留 60 秒，并标记过期采样；没有有效值时显示“—”。多个来源有有效采样时相加。
- 上传、下载和内存：已有服务的真实遥测。网络字节不能换算为 token。

本机日志路径分别遵循 `CODEX_HOME`（默认 `~/.codex/sessions`）、`CLAUDE_CONFIG_DIR`（默认 `~/.claude/projects`）和 `DSH_HOME`（默认 `~/.dsh/sessions`）。DeepSeek 支持 Harness 的 `session.v4.jsonl.zstd`。不读取浏览器聊天或云端任务，不修改客户端设置或安装插件。

## 进度判定

参考 [codex-pacer](https://github.com/RyanZhangNTU/codex-pacer) 的进度证据原则：仅接受专用进度工具及成功确认，兼容已安装的 Pacer 进度上报；不从用户消息、普通工具参数、耗时或 token 数推算完成百分比。新回合重置进度，等待输入、失败和中断分别显示；正常结束才显示 100%。未启用对应进度上报时，仍可监测生命周期，但百分比保持未知。

监测器每 10 秒发现日志，每来源最多保留 16 个近期文件；单次压缩/原始读取总量限制为 2 MiB，解压输出限制为 8 MiB。日志以增量方式读取，半行或未完成的压缩帧留待下一次读取。界面只接收状态、计数和速率，不接收提示词、回复或日志路径。

本机活跃状态来自日志，不能证明模型未来一定完成；停止更新的旧任务会从活动集合中过期。没有实际安装的客户端通过格式回归测试覆盖，不能视为真实客户端端到端验证。
