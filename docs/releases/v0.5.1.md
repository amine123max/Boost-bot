# Boost 0.5.1

[简体中文](v0.5.1.zh-CN.md) · [Release assets](https://github.com/amine123max/Boost-bot/releases/tag/v0.5.1)

This refresh hardens local storage, management scheduling and inference admission across the desktop and self-hosted runtimes. It also preserves the 0.5.1 Bot workspace, source-specific models, signed channel integration and compact task/approval interfaces.

## Storage and key management

- Main storage verifies SQLite WAL, foreign keys, NORMAL synchronization and a 5-second busy timeout. Startup performs an integrity check; routine maintenance uses passive checkpoints.
- SQLCipher is included in the default native build. Encryption is explicitly enabled with a system credential store or an external 32-byte key file. Plain databases undergo a verified staging conversion; wrong or missing keys fail without replacing the original database.
- Bot storage remains SQLite, using a native multiple-cipher binding with authenticated ChaCha20. Actor-specific keys derive from the main key and enter the managed host through private stdin. Existing Bot databases convert on the next host start.
- Request/token settlement is atomic and deduplicated. Wallet debit checks prevent duplicate charges in concurrent retries.

Encryption covers databases; workspace files, logs and exports need their own protection. Preserve the original key when moving encrypted data between machines. No automatic backup or key rotation is introduced.

## Scheduling and overload control

| Boundary | Default |
| --- | --- |
| Management writes | 6 executing; at most 256 waiting globally and 32 per resource domain |
| Management reads | 16 executing, with explicit capacity rejection |
| Inference rate | 20 QPS, burst 20; optional per-key RPM |
| Inference concurrency | 24 globally, 8 per model, with storage-pool headroom |
| Request memory | 32 MiB per body; 64 MiB reserved body budget |
| Source circuit | 60-second window, minimum 20 samples, over 50% failures, 30-second open interval |

Resource-domain FIFO queues precede global write acquisition; cross-domain mutations retain an exclusive barrier. Both RPC entrypoints share the same budgets. Stream completion, cancellation and errors release admission. Temporary overload returns 429 instead of creating an unbounded queue.

Quota-limited text requests reserve a conservative input/output budget before dispatch. Reservations are process-local and do not promise crash-safe or cross-process accounting. Source circuits distinguish account and aggregate upstreams; half-open probes are bounded. The front proxy forwards uploads with backpressure, WebSocket input is bounded, and trace queues cannot be unbounded.

## Desktop and operations

- Desktop updates verify an Ed25519-signed manifest binding the repository, tag, source commit, platform, asset size and SHA-256; files are checked again before application.
- The service launcher restarts owned children with bounded exponential delays and a consecutive-failure limit. Shutdown gives owned services a longer exit window.
- A dedicated settings connection removes repeated schema initialization from hot authorization reads.
- Gateway controls are under **Settings → Boost advanced settings → Gateway settings**. Explanations use focusable SVG hints; storage security displays key source and integrity state.
- Public technical documentation is maintained as paired English/Chinese files. The README retains the project overview, diagrams, spaced screenshots, latest-release links and Star history.

## Verification and limitations

See [load validation](../PERFORMANCE.md), [validation commands](../../TESTING.md) and the [technical boundaries](../../ARCHITECTURE.md). Load results use an isolated local mock, not a real-provider latency guarantee. Budgets apply per process. Durable quota recovery, full audit logging, key rotation, operating-system sandboxing and reconciliation remain separate work.
