# Boost 0.5.0

[简体中文](v0.5.0.zh-CN.md) · [Historical release](https://github.com/amine123max/Boost-bot/releases/tag/v0.5.0)

The first stable desktop release combines account management, an OpenAI-compatible gateway and a managed Bot workspace. This document describes the historical release; current configuration and security behavior are documented in the [build guide](../BUILDING.md).

## Scope

| Component | Released capability |
| --- | --- |
| Accounts | Import, authorization status, availability, usage windows and routing preferences |
| Gateway | Responses and Chat Completions, JSON/SSE, tools, model mapping and aggregate upstreams |
| Access and usage | Platform keys, model permissions, quotas, prices, request logs and statistics |
| Bot | Conversations, memory, tasks, approvals, channels and tool permissions |
| Desktop | Tray, themes, floating monitoring, local task-log observation and user-controlled updates |
| Deployment | Desktop plus source-built Service/Web and Docker deployment |

Gateway and channel capabilities depend on upstream credentials, quotas and host permissions. Historical telemetry uses actual output-token sampling; sources without reported progress remain indeterminate.

## Assets and installation

| Platform | Historical asset |
| --- | --- |
| Windows x64 portable | Boost_0.5.0_x64.exe |
| Windows x64 installer | Boost_0.5.0_x64-setup.exe |
| macOS Apple Silicon | Boost_0.5.0_aarch64.dmg |

Download from the linked historical release and verify its SHA-256 file. Windows needs WebView2. On macOS, open the DMG and move Boost.app to Applications; this release was not Apple-notarized. Source archives are not runnable desktop packages. No Intel Mac, Linux desktop or Windows ARM64 installer was included.

Exit running instances before upgrading. Portable packages prepare the embedded Node/Bot runtime on first launch. Settings, databases, logs and caches use the user .boost directory; deleting the executable does not remove that data.

## First connection

Start Boost, add an account or aggregate upstream, configure models and create a platform API key. A local compatible client uses http://localhost:12580/v1 with that platform key. Management Web access uses http://localhost:12000. Check request logs after the first call. Provider secrets belong in upstream configuration rather than client configuration.
