# Boost 0.5.1

[English](v0.5.1.md) · [发行附件](https://github.com/amine123max/Boost-bot/releases/tag/v0.5.1)

本次刷新加强桌面与自托管运行时的存储、管理调度和推理准入，同时更新 Bot 对话执行、历史重新生成和任务进度，保留独立模型来源、签名渠道和紧凑任务/审批界面。

## 存储与密钥

- 主库核验 SQLite WAL、外键、NORMAL 同步和 5 秒忙等待；启动执行完整性检查，常规维护采用被动 checkpoint。
- 默认原生构建包含 SQLCipher。通过系统凭据库或外部 32 字节密钥文件显式启用加密；明文旧库经暂存转换和校验后切换，错误或缺失密钥不会替换原库。
- Bot 继续使用 SQLite，通过原生多密码绑定启用带认证的 ChaCha20。按身份派生的独立密钥通过私有标准输入传给受管宿主；既有 Bot 库在对应宿主下次启动时转换。
- 请求与 Token 结算原子提交并去重；钱包扣费在事务内检查重复，防止并发重试重复扣款。

加密范围为数据库，工作文件、日志和导出仍须独立保护。跨设备迁移必须保留原密钥。本次不引入自动备份或密钥轮换。

## 调度与过载保护

| 边界 | 默认策略 |
| --- | --- |
| 管理写请求 | 6 个执行；全局最多 256 个等待，每资源域最多 32 个等待 |
| 管理读请求 | 16 个执行，超容量明确拒绝 |
| 推理速率 | 20 QPS、突发 20；每密钥 RPM 可选 |
| 推理并发 | 全局 24、每模型 8，并为存储池保留余量 |
| 请求体内存 | 单体 32 MiB、总预留 64 MiB |
| 来源熔断 | 60 秒窗口、至少 20 样本、失败率超过 50%、开启 30 秒 |

资源域 FIFO 排队先于全局写名额获取，跨域变更保留独占屏障；两种 RPC 入口共享预算。流式完成、取消和错误都会释放准入资源，临时过载返回 429，避免无限积压。

累计 Token 受限的文本请求在转发前预留保守输入/输出预算。预留仅作用于进程内，不承诺跨进程或崩溃恢复记账。熔断区分账号与聚合来源，半开探测数量受限。前置代理按背压转发上传，WebSocket 输入有界，跟踪队列不可配置为无限队列。

## Bot 对话与任务进度

- 托管对话不再继承旧的总回合或空闲截止时间；主动停止、提供商错误、单个工具限制及后台任务预算仍然生效。
- 消息接收与回复流独立。执行中可以发送补充；代理支持时并入当前回合，否则按会话顺序等待。
- 历史编辑更新同一会话中的原用户消息，保留 ID 和时间。先停止旧回复、移除其后续分支，再按保留历史重建执行上下文；已经发生的外部工具副作用无法撤销。
- 授权辅助模型负责将真实记录归纳为大小节点，未配置时使用选定主模型，覆盖对话、后台任务和定时运行。每次运行独立绑定证据和进度缓存，未执行任务不能凭空获得完成状态。
- 后台下拉仅显示对应任务的层级、状态与进度，移除独立会话计划卡片、AI 标题、节点数量和详情按钮。处理区执行中显示“已处理 xx 秒”，结束后显示“已完成”。
- 节点分析限制为两路执行、八个等待、25 秒截止，合并相同并发请求；执行中至少间隔 30 秒刷新，失败冷却 60 秒。超额请求明确拒绝，避免无限积压。

## 桌面与运维

- 更新器校验 Ed25519 签名清单，将仓库、tag、源码提交、平台、文件大小与 SHA-256 绑定；应用前再次校验文件。
- 服务启动器以有界指数退避重启自己启动的子进程，连续失败达到上限停止重启；正常关闭保留更长退出时间。
- 设置读取使用专用缓存连接，避免授权热点反复初始化 schema。
- 网关控制位于**设置 → Boost 高级设置 → 网关设置**。解释信息收进可键盘访问的感叹号 SVG 提示，存储安全显示密钥来源与完整性状态。
- 公共技术文档中英文配套；README 保留项目顶部、架构图、有间隙的截图、最新 Release 入口和 Star 增长曲线。

参阅[负载验证](../PERFORMANCE.zh-CN.md)、[验证命令](../../TESTING.zh-CN.md)和[系统架构](../../ARCHITECTURE.zh-CN.md)。Bot 浏览器回归通过隔离模型覆盖处理中补充、原消息重新生成、任务隔离、仅节点下拉及计时/完成标题；这些 fixture 不验证真实提供商的 AI 输出或延迟。预算按进程计算。持久配额恢复、全量审计、密钥轮换、操作系统沙箱与对账仍属后续工作。
