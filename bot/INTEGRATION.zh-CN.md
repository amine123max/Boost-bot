# 受管运行时集成

[English](INTEGRATION.md) · [Bot 概览](README.zh-CN.md) · [系统架构](../ARCHITECTURE.zh-CN.md)

## 所有权与启动

Rust 服务负责 actor、平台 key、来源 broker 租约、子进程生命周期和受权代理；Node 负责会话、智能体、任务、渠道、审批和工作目录工具。FastAPI/Nginx 是可选接入层。

受管宿主通过有界私有 stdin 记录接收数据路径、loopback 网关、有归属 key、启动令牌、身份权限和可选派生数据库密钥，秘密不放入命令行。Node 校验可信地址、登记脱敏值，并在打开状态前取得目录锁。

| 边界 | 约定 |
| --- | --- |
| Actor 范围 | 可信角色/用户的稳定摘要 |
| 启动令牌 | 宿主内部 HTTP 授权 |
| 平台 key | 经 Boost 执行模型权限、归属与计费 |
| 来源 broker | 服务端选择有权限的账号/聚合模型 |
| 数据库密钥 | 主密钥经 HMAC-SHA256 按身份独立派生 |
| 数据锁 | 拒绝并发占用与不安全迁移 |

未传密钥的独立明文模式保持兼容；受管加密模式在正常启动前转换并验证 Bot SQLite。工作文件、日志和任意输出不属于数据库加密。

## HTTP 与流式传输

Web 验证浏览器并推导 actor，Service 选择对应宿主；调用者不能指定内部身份。传输链保留请求/响应字节、query 和 SSE 格式；断连释放上游连接及准入预留。

可选 Python 网关仅指向固定可信 Boost Web，剥离内部 actor/RPC 头，限制活跃、等待和输入内存，不自动重放写请求。参见 [FastAPI](backend/api/README.zh-CN.md) 和 [Nginx](../nginx/README.zh-CN.md)。

## 模型与执行

Bot 只能绑定身份可见来源，目录发现不授予访问权限，映射保持账号池和聚合连接区分；工具权限独立于模型是否可用。

DSH 提供真实执行、工具与审批。界面区分结构化计划和历史活动，不能补造思考、审批、进度或完成事件。群协作保留成员关系与文件访问检查。

### 对话生命周期

受管对话关闭总回合和空闲截止时间，包括旧配置中的非零值；独立模式两项默认也为零。主动停止、提供商错误及单项工具/审批策略仍然生效。网页单聊和群聊的消息进入有界 SQLite 队列。后续消息按会话顺序等待，只有用户主动选择「引导」且当前智能体支持插话时才并入本轮；待发项可编辑和移除。刷新后重接当前回合，宿主重启后未发送消息继续排队；上次中断的执行留给用户核对后决定是否重发。

随包 DSH SDK 适配层仅发布原会话的公开正文增量。Vue 工作台通过 SSE 接收带偏移量的正文增量，断线后从最新快照续接；旧订阅端仍可接收累计正文。浏览器按显示帧追加收到的文字，结束后才完整解析 Markdown。只提供最终 JSON 的上游仍只显示最终回复。回复展示已处理时间，实际工具状态放在对应正文下方，不公开模型推理和工具原始参数／输出。成功的结构化文件操作会显示文件卡片，有已应用的差异时显示行数。网页提问位于输入框上方，支持选项、自由输入和跳过；关闭卡片会保留待答问题。

DSH 和纯对话共用回答规则，要求延续原有目标与约束、区分证据和推断，并按问题复杂度提供足够细节。纯对话明确没有执行工具；会话从纯对话返回 DSH 时，会补上同一会话的近期消息。两条路径都使用显式设定的模型协议，只在已知模型和接口支持时传递推理强度。受管宿主的工具权限独立于提示词和模型设置。

刷新网页或 SSE 中断后，工作台自动重读历史并订阅最新快照，不会重发消息。任务结果、提醒和问题只更新所属会话；微信和飞书账号按绑定的 Bot 展示和投递。

历史重新生成更新原用户消息行，保留会话、消息 ID、时间和之前的上下文。服务端先停止并等待旧回复结束，移除当前分支此后的消息，再按保留上下文重建智能体执行会话。原文校验拒绝过期编辑；重新生成无法撤销已经发生的外部工具副作用。提交编号在凭据保留窗口内防止重复执行。

### AI 任务层级

普通对话不启动任务拆分。单聊输入 `/task` 打开新增任务表单，经现有调度器创建的任务同时出现在输入框上方和该智能体的任务列表。用户自带的清单可在执行前即时展示；任务或定时运行由授权辅助模型归纳实际证据，未配置时使用主模型，最多六个大节点、每个最多五个子节点。完成状态必须有成功证据，未知进度留空，详细诊断保留在任务管理。

分析限制为两路执行、八个等待、15 秒截止；合并相同并发请求，执行中至少间隔 30 秒刷新，失败冷却 60 秒。SQLite 缓存按模型绑定和证据失效，每个 Bot 保留最近 32 份分析。折叠的任务面板和隐藏页面不发起分析。

## 存储与迁移

Bot 数据库保存会话、记忆、渠道凭据、审批、任务和出站交付。SQLite 使用 WAL、有界锁等待和支持加密的原生 Node 驱动。暂存转换验证 schema、行数、rowid、自增高水位、整数和 BLOB；不支持的虚拟表拒绝转换，不产生半转换库。

数据与工作目录迁移在渠道/调度器之前执行。当前和待应用路径分开，已有目标不合并，链接和中断状态明确。SQLite 原生扩展须匹配 OS/架构/Node ABI；准备脚本拒绝跨架构直接复制。

## 宿主工具与语音

在 Bot 会话右侧打开「宿主工具」。受管部署中，只有系统管理员可查看本机进程名称和 PID，以及 Codex、Claude Code 和 DeepSeek Harness 可读日志中的状态摘要。仅当来源提供进度时才显示百分比。观察范围限于运行 Boost 的机器和系统账号；不会接管或停止其他 Agent。可信的完全访问 Bot 还可在活动网页对话中调用 `task_inspect` 查询有权访问的 Bot 任务，或调用 `host_activity` 读取宿主快照。

电脑控制默认关闭。有可用驱动和交互式桌面会话时，可为受信任的 Bot 启用。新配置的点击和输入动作需审批，平台和辅助功能权限以宿主驱动要求为准。无头服务没有交互桌面可供操作。

添加自定义插件时，先在宿主单独运行可信的 Streamable HTTP MCP 服务，再在面板填写唯一标识及类似 `http://127.0.0.1:3001/mcp` 的地址。每个 Bot 最多配置八个服务。只有完全访问的可信 Bot 可在活动网页会话中经审批调用。插件按启动服务的系统账号权限运行；仅配置信任的服务及其重定向目标。面板不会安装或执行插件代码。

语音使用 Whisper 多语言 Tiny Q5_1（32,152,673 字节，SHA-256 为 `818710568da3ca15689e31a743197b520007872ff9576237bda97bd1b469c3d7`）。在已安装 Bot 依赖的源码目录运行 `node bot/scripts/prepare-voice.mjs "<Bot 数据目录>/voice"`。脚本校验模型并在 Windows x64 下载固定版本的 CPU CLI；其他平台需安装 whisper.cpp v1.8.3 并将 `whisper-cli` 加入 PATH。Ogg/Opus 等编码需要 FFmpeg；SILK 和 16 kHz 单声道 PCM WAV 无需 FFmpeg。打包时设置 `BOOST_BOT_BUNDLE_VOICE=1` 可将校验过的资产放入 `bot/dist/voice`，默认构建不附带权重。可用 `BOOST_BOT_VOICE_DIR`、`BOOST_BOT_VOICE_WHISPER` 和 `BOOST_BOT_VOICE_FFMPEG` 指定资产目录及程序路径。

微信、飞书和受支持的 Telegram 语音消息优先使用渠道转写。没有转写时由 Bot 在宿主本地识别，再将文本交给所选模型，向原渠道回送文字。每段最多 8 MiB，最多处理 90 秒，每个 Bot 宿主同一时间处理一段语音，允许三段等待。

## 打包

prepare 脚本使用锁定依赖并构建后端/UI，stage 脚本将运行时与许可放入服务包。Tauri 从根 Bot 目录打包，不在桌面包复制源码。

内置技能、persona 和模板属于运行输入，不是公开部署指南；文档维护不能改变它们的入口和语义。第三方许可保留原文。
